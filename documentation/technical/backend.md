# Backend Technical Reference

## Layout

```
backend/
├── src/
│   ├── index.ts              entry point: middleware order, routers, static frontend, server start, shutdown
│   ├── config/env.ts         environment validation, exports `config`
│   ├── auth/                 model.ts (Better Auth tables), auth.ts (setup), mailer.ts (Resend), router.ts
│   ├── profiles/             model.ts (table, `username_holds` table, Zod, messages), repository.ts, service.ts, router.ts, tests
│   ├── accounts/             model.ts (confirm rule, message), repository.ts (deletion transaction), service.ts, router.ts (`DELETE /me`), tests
│   ├── statements/           model.ts (table, text rule, serializers, SQL fragments, messages), repository.ts, service.ts, router.ts, tests
│   ├── drops/                model.ts (table, send schema, inbox query, cursor, serializer, messages), keys.ts, limits.ts, repository.ts, service.ts, router.ts, tests
│   ├── photos/               model.ts (limits, messages), service.ts (cleanPhoto, newPhotoKey), service.test.ts
│   ├── places/               model.ts (cache table, LocationIQ reading), client.ts, repository.ts, service.ts, tests
│   ├── link-preview/         router.ts (GET /:username), service.ts (HTML rendering), tests
│   ├── health/               router.ts (health, ready), service.ts (database check), router.test.ts
│   ├── middleware/           rate-limit.ts, session.ts, same-origin.ts, security-headers.ts, device-cookie.ts, tiles.ts
│   └── shared/               db/client.ts (pool, `db`, `closeDb`), db/ssl.ts (`withoutSslParams`), db/citext.ts, db/geography.ts (PostGIS point type, EWKB parser), errors.ts (AppError with optional retryAfterSeconds, errorHandler), fixed-window.ts, user-limiter.ts (per-user limiter), geo.ts (location rounding), storage/model.ts (FileStore type), storage/key.ts (key check), storage/local-disk.ts (disk store), storage/supabase.ts (Supabase store)
├── drizzle/                  migrations (SQL) and the Drizzle journal
├── drizzle.config.ts         Drizzle Kit settings, reads `../.env`
├── tsconfig.json
└── package.json
```

Compiled output goes to `backend/dist/`. The server serves `frontend/dist/` for every path outside `/api`, and falls back to `index.html` so the frontend router handles the path.

## Commands

Run from `drop-app/`.

| Command            | Does                                                              |
| ------------------ | ----------------------------------------------------------------- |
| `pnpm dev:backend` | `tsx watch` on `src/index.ts`, reads `drop-app/.env` if present   |
| `pnpm build`       | Builds the frontend, then `tsc` compiles the backend into `dist/` |
| `pnpm start`       | `node dist/index.js`, reads `drop-app/.env` if present            |
| `pnpm typecheck`   | `tsc --noEmit`                                                    |
| `pnpm test`        | `vitest run src`                                                  |
| `pnpm db:generate` | `drizzle-kit generate`, reads `drop-app/.env`                     |
| `pnpm db:migrate`  | `drizzle-kit migrate`, applies pending migrations                 |

Validation messages (exported from `profiles/model.ts`, mirrored by the frontend): "Use 3 to 30 letters, numbers, dots or underscores.", "That name is reserved.", "That name is taken.", "Enter a display name up to 50 characters.", "Send at least one field to update.". Reserved usernames: api, admin, sign-in, signin, sign-up, signup, claim, home, inbox, map, settings, playground, help, about, terms, privacy, safety, drop, drops, me, profile, profiles, login, logout, auth, support, static, assets, brand, landing, marble, favicon.svg, icons.svg, index.html, robots.txt.

Send validation messages (`drops/model.ts`): "Write a message up to 280 characters.", "That location is not valid." (coordinates out of range or malformed), "Turn on your location to send a drop." (`LOCATION_REQUIRED_MESSAGE`: location missing, partial, or not from GPS), "This link is not taking drops right now." (`LINK_CLOSED_MESSAGE`, error code `LINK_CLOSED`), "Use a JPEG, PNG or WebP photo up to 8 MB." (`PHOTO_MESSAGE`, `photos/model.ts`; also a decodable image of another format), "That photo could not be read." (`PHOTO_UNREADABLE_MESSAGE`; bytes sharp cannot decode, or over 40 megapixels). The device cookie is `__Host-drop_device` when `BETTER_AUTH_URL` is https, `drop_device` otherwise. The frontend loads map files from same-origin URLs such as `/tiles/philippines.pmtiles`, `/tiles/fonts/{fontstack}/{range}.pbf` and `/tiles/sprites/v4/light`.

Inbox item (one serializer, `toInboxItem` in `drops/model.ts`, used by list, detail and mark read): `{ id, message, location: { lat, lng, name, source }, has_photo, is_read, statement_id, created_at }`. `statement_id` is the statement the drop was sent under, null for a drop from before statements. `lat` and `lng` are the stored rounded cell centre, `name` is the place name or null, `source` is `gps`, `created_at` is an ISO time. The photo key never leaves the server.

Statement (one owner-facing serializer, `toStatement` in `statements/model.ts`, used by create, end, current and the `statements` field of the drops list): `{ id, text, started_at, ends_at, ended_at, running, seconds_left, drop_count }`. Times are ISO strings; `ended_at` is null while open; `running` is true when `ended_at` is null and `ends_at` is ahead of the database clock; `seconds_left` is whole seconds to `ends_at`, rounded up, 0 once ended; `drop_count` is every drop filed under it. The public shape (`toPublicStatement`) is `{ text, ends_at, seconds_left }` and is returned only inside the public profile.

Statement rules (`statements/model.ts`): `STATEMENT_DURATION_SECONDS` is 7200 (2 hours), `STATEMENT_MAX` is 120. The text is a string whose whitespace runs (newlines included) collapse to one space and is trimmed, then must be 1 to 120 code points with no NUL or other C0 control character (`/[\u0000-\u001F\u007F]/`); every failure gives "Write a statement up to 120 characters." Messages: `STATEMENT_MESSAGE`, `STATEMENT_ENDED_MESSAGE` ("That statement has already ended."), `END_BODY_MESSAGE` ("Send ended as true."). `createStatementSchema` and `endStatementSchema` are strict objects carrying their own 422 message. The running condition and the seconds-left expression are SQL fragments (`runningSql`, `secondsLeftSql`) shared with the drops repository, so one database clock decides.

Statement service (`statements/service.ts`): every call resolves the signed-in user's profile first (`404` if none). `startStatement` calls the repository `start`: one transaction that locks the profile row `FOR UPDATE`, sets `ended_at = greatest(started_at, least(now(), ends_at))` on the open row (so a statement that ran out keeps its own end time), and inserts the new row with `ends_at = now() + make_interval(secs => 7200)`. `endStatement` validates the id as a UUID (else `404`), locks the profile row, then runs a conditional `UPDATE ... WHERE id AND profile_id AND running`; with no row updated it selects by id and profile to answer `404` (missing or foreign) or `409 STATEMENT_ENDED`. `getCurrent` answers `{ statement }`. Repository reads also give `findRunningId` (cheap check for the send flow) and `summariesFor(profileId, ids)` (statements of that profile only, with drop counts, newest first; an empty list skips the query). A foreign id never matches because every query filters by profile.

Inbox cursor: base64url of `<created_at at microsecond precision, UTC>|<id>` of the last item. It is decoded and checked on every request (length at most 120, URL-safe characters, a real time, a UUID); a bad cursor gives `422`. The page query is `(created_at, id) < (cursor)` ordered `created_at DESC, id DESC` and fetches one extra row to know whether a next page exists.

Inbox service (`drops/service.ts`): every call resolves the signed-in user's profile first (`404` if none), then queries by recipient and id together, so another user's drop is never matched. `listInbox` runs the page query and `countInbox` (one query with `count(*) FILTER` for unread and for `statement_id IS NULL`) in parallel, then reads the statements for the page through `findStatementSummaries`. Delete removes the row and then the file; a failed file removal is logged as "Photo file could not be removed" without the key and does not fail the delete. The service takes `findOwnProfile` as a dependency.

## Accounts

`accounts/` owns `DELETE /api/v1/me`. The body is `{ username }`, a strict object (`deleteAccountSchema`): a string, trimmed, lowercased, 1 to 30 characters. `CONFIRM_MESSAGE` is "Type your link name to confirm." The router answers it with `422` for every body problem, so no Zod text ever reaches the client.

Account repository (`accounts/repository.ts`, `deleteAccount(userId, confirmUsername)`): one transaction.

1. Select the caller's profile `FOR UPDATE`. This conflicts with the `FOR SHARE` lock `insertDrop` takes, so a drop being sent at the same moment either commits first (its photo key is read in step 4) or runs after, finds no profile and removes its own file. No profile gives `missing`.
2. Compare the stored username with the typed one, lowercased. A difference gives `mismatch` before any write.
3. Read the `photo_key` of every drop sent to the profile.
4. Upsert `username_holds` with `released_at = now() + make_interval(days => 30)` (`USERNAME_HOLD_DAYS`).
5. Delete the `user` row. The cascade removes the sessions on every device, the auth account, the profile, the drops and the statements. Result `{ status: "deleted", photoKeys }`.

Account service (`accounts/service.ts`): `missing` throws `404 NOT_FOUND` "Not found", `mismatch` throws `422` `CONFIRM_MESSAGE`. After the commit it removes the photo files in batches of 10 with `Promise.allSettled`. A file that cannot be removed does not undo the deletion, because no row points to it. The failure count is logged as `Photo files could not be removed:` plus the number, never a key, email or name. Leftover files wait for an orphan sweep (open item in the progress note).

Account router (`accounts/router.ts`, `createAccountRouter(service, { origin, clearSession, limit = 5 })`): `Cache-Control: no-store` is set first so errors carry it too. The route runs the same-origin guard, `requireUser`, the per-user limiter (5 per minute), the 1 KB body limit, then the `application/json` content type check, the strict parse, the service call, and the session clearing. `clearSession(headers)` is built in `index.ts` from Better Auth: `auth.api.signOut({ headers, returnHeaders: true })` deletes the session row and returns `Set-Cookie` headers that clear the session cookies. The router appends each one to the reply, then answers `204`.

Username holds (`profiles/model.ts`): table `username_holds` (`username` citext primary key, `released_at` timestamptz not null, index `username_holds_released_at_idx`) and `USERNAME_HOLD_DAYS` 30. `profiles/repository.ts` `insertProfile` runs in one transaction: delete holds whose `released_at` has passed, look for a hold on the username (a hit returns `{ conflict: "username" }`), then insert the profile. A held name answers `409 USERNAME_TAKEN` "That name is taken.", the same as a taken one, so the page never says someone deleted it. The public availability check does not consult holds, so a held name reads as free until the claim is submitted.

## Middleware order

`index.ts`: global error handler; security headers on all paths; `/api/*` rate limiter; `/api/*` session middleware (sets `c.var.user` and `c.var.session`, null when signed out; `requireUser` answers `401`); auth router; health router; profiles router; drops router; statements router; accounts router; `/api/*` 404; tiles router at `/tiles`; static files; link preview router (`GET /:username`); `index.html` fallback. The device cookie middleware runs on `/api/v1/profiles/*` and sets `c.var.deviceId`, so the first profile read sets the cookie. The inbox routes run `requireUser` and the per-user limit; `PATCH` and `DELETE` also pass the same-origin guard first. The guard (`middleware/same-origin.ts`, `createSameOriginGuard({ origin })`) lets GET, HEAD and OPTIONS through and, for every other method and whatever the content type, passes only when `Origin` equals the app origin or `Sec-Fetch-Site` is `same-origin`; otherwise `403 FORBIDDEN` "Request not allowed" in the envelope. It replaced Hono `csrf`, which skipped JSON bodies. The drops send route runs the guard, then the 9 MB body limit, then the content type, then parses the multipart body, then calls the service. The statements routes run the guard (POST and PATCH), `requireUser`, the write limiter, the 1 KB body limit and a strict JSON parse, and every statements response sets `Cache-Control: no-store`.

Send service order (`drops/service.ts`): resolve the recipient (`404`), check that a statement is running (`409 LINK_CLOSED`, before any limit is counted), rate limit, validate (`422`), clean the photo if present (`422`, nothing written yet), round the location, look up the place name (a failure gives a null name), save the photo to the file store, insert in a transaction that locks the profile row `FOR SHARE`, selects the running statement `FOR SHARE` (none gives `closed`) and files the drop under its id; the row type has no statement field, so a caller cannot choose it, and a client `statement_id` fails the strict send schema with `422`. If the insert throws, or returns closed or missing, the saved file is removed before the error is raised. Slots are left for the block check (module 11), text moderation (deferred), the automatic photo check (deferred) and the notification (module 10). The service takes `store`, `cleanPhoto` and `newPhotoKey` as dependencies.

## Security headers

`middleware/security-headers.ts` (Hono `secureHeaders`): `Strict-Transport-Security: max-age=31536000; includeSubDomains`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, plus Hono defaults (COOP and CORP same-origin). Content Security Policy: `default-src self`; `script-src self`; `style-src self`; `font-src self`; `img-src self data: blob:`; `connect-src self`; `worker-src self blob:`; `object-src none`; `base-uri self`; `form-action self`; `frame-ancestors none`. The built landing page runs under it with no violations in Edge at 390 and 1280 px.

## Auth

`auth/auth.ts` (Better Auth, `basePath /api/auth`, Drizzle adapter, `trustedOrigins` = `BETTER_AUTH_URL`, telemetry off): email password disabled; `emailOTP` plugin (6 digits, 300 s expiry, 3 attempts, sends only for `sign-in` through `auth/mailer.ts` and Resend). Session lifetime 7 days, refreshed after 1 day. Cookies `httpOnly`, `SameSite=Lax`, `Secure` when `BETTER_AUTH_URL` is https. Better Auth rate limit on in every environment, in memory: 30 per 60 s per path, `send-verification-otp` 3 per 60 s, `sign-in/email-otp` 10 per 60 s. The auth router overwrites `x-forwarded-for` with the socket address so the limits count real clients; behind a proxy this must change to the trusted proxy address. Codes and email addresses are never logged. Account deletion reuses `auth.api.signOut` only to produce the cookie-clearing headers (see Accounts); Better Auth's own `deleteUser` is not used. Session rows hold the raw network address (`ip_address`) and browser (`user_agent`) for up to 7 days, so PRD 7.1 "raw IPs never written" holds for senders only.

## Rate limiting

`src/shared/fixed-window.ts` is the shared counter (`peek`, `hit`, injectable clock, pruned on an unref'd timer). Everything below is held in memory, per instance, and reset on restart. IPs come from `getConnInfo`, no proxy headers.

- `src/middleware/rate-limit.ts`, applied to `/api/*`: 60 requests per minute per IP. Over the limit: `429`, `error.code: "RATE_LIMITED"`, `Retry-After` in seconds.
- `drops/limits.ts` (`createSendLimiter`), inside the send service: 60 per hour per IP, 30 per hour per device, 5 per 15 minutes per device and recipient. A send is counted only when all three have room. Over the limit it throws `AppError(429)` with the longest wait, and the global handler sets `Retry-After`. Only hashed keys are held.
- `shared/user-limiter.ts` `createUserLimiter({ limit, windowMs = 60000, now? })`, keyed by the signed-in user id, used by the drops, statements and accounts routers. Drops: 120 per minute shared by `GET /drops`, `GET /drops/:id`, `PATCH` and `DELETE`; 300 per minute for `GET /drops/:id/photo`. Statements: 10 per 15 minutes shared by `POST /me/statements` and `PATCH /me/statements/:id`, and 60 per minute for `GET /me/statements/current`. Accounts: 5 per minute for `DELETE /me`. Over the limit: `429`, `RATE_LIMITED`, `Retry-After`.
- `middleware/tiles.ts`: 600 per minute per IP on `/tiles/*`, outside the API limiters.

Sender keys (`drops/keys.ts`): HMAC-SHA256 hex of `ip:` plus the normalized IP (IPv4-mapped IPv6 reduced to IPv4, other IPv6 reduced to its /64), and of `device:` plus the device id, keyed by `SENDER_KEY_SECRET`.

## Photos and file storage

`photos/service.ts` `cleanPhoto(bytes)` reads the format from the bytes with sharp (only jpeg, png and webp pass), opens the image with `limitInputPixels` 40,000,000 and `pages: 1` (first frame only), applies the EXIF orientation, resizes to fit inside 1080 by 1350 without enlarging, and writes WebP with no metadata (no EXIF, no GPS). Quality steps 82, 72, 62, 52 until the output is at most 400 KB; if none reaches it, the smallest is kept. Any sharp error gives `422` with "That photo could not be read." and nothing about the image is logged. `newPhotoKey()` is `<random UUID>.webp`.

`shared/storage/model.ts` defines `FileStore` (`save(key, bytes)`, `read(key)`, `remove(key)`). `shared/storage/local-disk.ts` implements it on `UPLOADS_DIR`: keys must match `^[a-z0-9-]{36}\.webp$` and the resolved path must stay inside the folder, otherwise it throws. `save` writes a random `.tmp` file and renames it, so a file appears whole or not at all. `remove` ignores a missing file. `shared/storage/key.ts` holds the key check both stores use. `shared/storage/supabase.ts` `createSupabaseStore({ url, secretKey, bucket, fetch })` implements it on Supabase Storage over REST (no extra package): `POST`, `GET` and `DELETE` on `{url}/storage/v1/object/{bucket}/{key}` with the secret key in `apikey` and `Authorization: Bearer`, saves as `image/webp` with `x-upsert: false`, each call limited to 10 s. A missing object on read (HTTP 404, or 400 with `not_found` in the body) throws an error with `code: "ENOENT"`, the same signal the disk store gives, so the photo route answers 404; a missing object on remove is ignored. Any other failure throws an error holding the status only, never the key or headers. The bucket is private, 2 MB, `image/webp` only. `index.ts` picks the Supabase store when `SUPABASE_URL` is set, else the disk store. No static route serves the folder; photos reach their owner only through `GET /api/v1/drops/:id/photo`. Deleting an account removes the files of all its drops after the commit (see Accounts).

## Location and places

`shared/geo.ts` `snapToGrid` rounds a point to the centre of a 150 m cell (latitude step 150/111320 degrees, longitude step widened by the cosine of the cell latitude, 6 decimals) and returns the cell key `<i>:<j>`. Only the centre is stored. `places/service.ts` returns the cached name for a cell if it is under 48 hours old (a cached null counts), otherwise asks LocationIQ (`us1.locationiq.com/v1/reverse`, 2.5 s timeout), caches the answer and deletes expired rows. Any failure gives a null name and caches nothing. The name is the place name, else neighbourhood, else suburb, plus the city, never a road or house number.

, the resolved path must stay inside the folder, the folder is created on first save, a save writes a temp file and renames it, and `remove` ignores a missing file. No route serves the folder; the owner-checked route that reads photos is module 10. The development database and files move to Supabase before deploy.

## Map files

`middleware/tiles.ts` serves `TILES_DIR` (git-ignored `drop-app/tiles/` by default) at `/tiles` with Hono's `serveStatic` from `@hono/node-server`. No compression is applied, so range responses are never gzipped. Content types: `.pmtiles` octet-stream, `.pbf` x-protobuf, `.json`, `.png`. The CSP lists no extra origin because everything loads from `self`. The server logs a one-line warning at boot when the folder does not exist. How to fill the folder (the extract, fonts and sprites) is in [frontend.md](frontend.md).

## Database

`src/shared/db/client.ts`: one `pg` pool (max 10, idle timeout 30 s, connect timeout 10 s) wrapped by Drizzle (`drizzle-orm/node-postgres`). With `DATABASE_CA_PATH` set, the pool connects with `ssl: { ca, rejectUnauthorized: true }` and a URL stripped of ssl settings by `withoutSslParams`, because node-postgres lets URL ssl settings override the option. `drizzle.config.ts` does the same, passing host, port, user, password and database separately, since its URL form takes no ssl option. Pool errors log only the error code. On SIGTERM or SIGINT the server stops accepting connections, calls `closeDb()`, and exits.

Schema files are `src/<feature>/model.ts` (matched by `drizzle.config.ts`). Migrations live in `drizzle/` and are applied by `pnpm db:migrate`, never on boot. Migration `0000_extensions` enables `postgis` and `citext`. Tables ship with the feature modules.
