## Tokens

- `useTweaks(folder, defaults, schema?)` from `@/lib/tweaks/use-tweaks` returns `defaults` unchanged. There is no live panel; a value is changed by editing the defaults in its `tokens.ts` file.
- `routes/playground/*` throw `notFound()` in `beforeLoad` when `!import.meta.env.DEV`. Their small route chunks are still emitted to `dist`.

## Design tokens

Values, bands, the app layout spec, motion and marble are in [design.md](design.md).

- Wrapper levels: `.section`, `.sub-section`, `.placement`, `.container` in `index.css` (components layer), spacing from `--section-padding`, `--section-gap`, `--sub-section-padding`, `--sub-section-gap`, `--placement-padding`, `--placement-gap`, `--container-padding`, `--container-gap` in `styles/tokens.css`. `.section` is capped at `--content-max`.
- Tailwind's own `container` utility is disabled with `@source not inline("container")` so the wrapper class stays fluid.
- Type scale (`@theme inline`, all `clamp()`): `text-display`, `text-heading`, `text-subheading`, `text-message-large`, `text-message`, `text-body`, `text-caption`, `text-mono`. Breakpoint `3xl` is 120rem.
- Motion tokens (`lib/motion/tokens.ts`): `fadeSlide`, `overshoot`, `bounceLand`, `springFollow`, `popScale`, `squash`, `stagger`, `pressFeedback`, `rippleReveal`, `letterStagger`, `nudge`, `iris`, `lightSweep`, `marbleDrift`, `shaderFadeIn`, `tabSpring`, `reducedFade`, plus `landingMotion` (not tweakable). Easing names come from `EASING_NAMES` in `lib/motion/easings.ts`; `cssEasing(name)` gives a `cubic-bezier()` or sampled `linear()` string for CSS and the Web Animations API.
- Marble (`lib/marble/tokens.ts`): `marbleDefaults` on the Marble folder, `MARBLE_PIGMENTS`, `MARBLE_GL`. Previewed at `/playground/marble`.
- Landing (`lib/landing/tokens.ts`): `landingDefaults` (`landingMotion` plus `load`, `card`, `streets`, `shader`), flattened to `landingFlatDefaults` for the Landing folder and rebuilt with `unflattenLandingTokens`.
- Scrollbar (`lib/scrollbar/tokens.ts`): `scrollbarDefaults` (`shared`, `hairline`, `area`), `scrollbarSchema`, `scrollbarCssVars`, `scrollAreaCssVars`.
- Goo (`lib/goo/tokens.ts`): `blur` (feGaussianBlur stdDeviation), `alphaContrast` and `alphaOffset` (feColorMatrix alpha row).

## Landing

- **Frame loop.** `useScrollTimeline({ rootRef, lenis, reduced, tokens })` runs one `requestAnimationFrame` loop. Each frame calls `lenis.raf(now)`, reads `lenis.scroll` (or `window.scrollY` without Lenis), builds `ScrollState` with `readScroll`, and calls every subscriber with `{ L, S, now, changed, relaid }`. Components subscribe through `useTimelineFrame` and read shared state with `useLanding()` (`LandingContext`).
- **Layout.** `buildLayout` measures the beats once and on resize. `groundAt(y, L)` returns `paper`, `dark` or `grey` for a page position; the nav and the scrollbar use it to flip ink.
- **Lenis** (`useLenis(enabled)`): `new Lenis({ autoRaf: false, syncTouch: false })`, held in a ref and exposed through `useSyncExternalStore`: subscribing creates the instance, unsubscribing (unmount, or `enabled` turning false) destroys it. Not created under reduced motion. In-page links go through `scrollToTarget` (`lenis.scrollTo`). The claim dialog calls `lenis.stop()` while open and `lenis.start()` on close; it carries `data-lenis-prevent`.
- **Background.** `BathPlate` owns the single canvas and drives the marble renderer in external mode (`frame(now)` from the loop). The stage gets `still-mode` when the live shader is off (reduced motion or a failure).
- **Reduced motion.** The root gets `.rm`; no Lenis, no canvas, still poster, final states.
- **Theme.** The route sets `data-theme="light"` on the root element in a layout effect (before the first paint) while mounted and restores the previous value on unmount. The stored theme choice is not applied to it.
- **Claim.** `ClaimIris({ request, onClosed })` runs `useUsernameCheck(name)` and shows its message in `#claim-msg` ("Checking the name", "That name is free.", or the mirrored invalid, reserved or taken message; an empty submit shows the invalid message). Submit sets a waiting flag; once the check is `available` (or `idle` with a valid name, when the lookup failed) it navigates once to `/sign-in?username=<name>` behind a lock. Escape and Back close it; focus returns to the opener. Lenis stop and start are unchanged.
- **Frame cost.** Nothing in the loop reads layout: the renderer keeps the canvas CSS size from its ResizeObserver, and measurements (`buildLayout`, panel widths, photo size) run only on relayout. The hairline arms one hide timer and re-arms it for the time left, so steady scrolling sets no timer per frame.
- **Frame timing** (production build via `vite preview` on 127.0.0.1, Edge, 390x844 at dpr 3, one wheel pass over the page, script time from CDP `Performance.getMetrics`):

## Auth and profiles

- **Routes.** `/sign-in` (`validateSearch: usernameFromSearch`), `/claim` (same search; `beforeLoad` redirects to `/sign-in` with the username when `getSession()` is null), `/home` (`beforeLoad` redirects to `/sign-in` when signed out, otherwise to `/inbox`). `usernameFromSearch` returns `{ username: undefined }` for an invalid value, because the router merges the raw root search under the validated one. Guards are for user experience; the server checks the session on every request.
- **Auth client** (`lib/auth/client.ts`): `createAuthClient` from `better-auth/react` with `baseURL: window.location.origin`, `basePath: "/api/auth"`, `plugins: [emailOTPClient()]`. `sendCode(email)` calls `emailOtp.sendVerificationOtp({ type: "sign-in" })`, `verifyCode(email, otp)` calls `signIn.emailOtp`, then `signOut()`, `getSession()` (data or null), `useSession`. Failures become `ApiError`; a 429 reads `X-Retry-After` into `rateLimitMessage`.
- **Session reuse.** `getSession()` keeps a signed-in result in memory for `SESSION_REUSE_MS` (30 000 ms) and returns it without a request while it is fresh. A null result is never kept. The kept session is cleared by `signOut()` (before the call) and by `apiRequest` on any 401, through `setUnauthorizedHandler` (`lib/api.ts`). Nothing is written to storage. The server still checks the session on every API request, so after a revoke elsewhere a guard can pass for up to 30 s, then API calls fail with 401 and the next navigation redirects.
- **Fetch wrapper** (`lib/api.ts`): `apiRequest<T>(path, init)` sends `Content-Type: application/json` only when `init.body` is a string, so a `FormData` body gets no content type and the browser adds the multipart boundary. It uses `credentials: "same-origin"`, unwraps `{ data, error }`, throws `ApiError(status, code, message)`. A `204` has no body and resolves `undefined` (delete). 429 reads `Retry-After` ("Too many tries. Try again in N seconds."). Network failure is status 0, `NETWORK_ERROR`. 5xx messages are replaced with a generic one. Aborts rethrow the `AbortError`.
- **Profile model** (`lib/profiles/model.ts`): `RESERVED_USERNAMES` and the five message constants copied from `backend/src/profiles/model.ts`; `checkUsername` (trim, lowercase, 3 to 30 of `[a-z0-9_.]`, not reserved), `checkDisplayName` (trimmed, 1 to 50), `usernameFromSearch`; types `PublicProfile`, `OwnProfile`, `CreateProfileInput`, `UpdateProfileInput`. Must stay in step with the backend file.
- **Profile calls** (`lib/profiles/api.ts`): `getPublicProfile(username, signal?)`, `getOwnProfile(signal?)`, `createProfile(input)`, `updateOwnProfile(input)`.
- **Hooks.** `useUsernameCheck(input)` returns `{ status, message, username }` with status `idle | checking | available | taken | invalid`: the client rule first (no request), then `GET /api/v1/profiles/:username` after 350ms (404 available, 200 taken), aborting the previous request; other failures give `idle` with the error message. `useOwnProfile()` returns `loading | ready | missing (404) | signed-out (401) | error`. `useCreateProfile()` returns `{ create, pending, error, clearError }`; a ref lock allows one request at a time and stays shut after success.
- **Sign-in.** Email checked against a simple pattern (max 254). After sending: "If that email can sign in, a code is on its way."; resend locked 60s with an `m:ss` countdown. The code input is `inputmode="numeric"`, `autocomplete="one-time-code"`, digits only, cut to 6 (no `maxLength`, so a pasted "123 456" survives). Every verify failure other than 429 or network shows "That code did not work. Check it or send a new one." After verify, `GET /me/profile` 200 goes to `/inbox`, anything else to `/claim` (which checks again).
- **Claim.** 409 `USERNAME_TAKEN` shows on the name field; 409 `PROFILE_EXISTS` or an existing profile goes to `/inbox`; a successful claim also goes to `/inbox`; 401 goes to `/sign-in`; 422 and 429 show under the form.
- **Styles.** `--auth-*` tokens in `styles/tokens.css` (card max width, padding and gap per band, radii, field and button heights, focus ring, enter motion, `clamp()` type for title, code and link). The card enters with a 600ms fade and 24px rise; under reduced motion a 200ms fade only, and the marble shows its still.

## Send page

- **Route.** `/$username` (`routes/$username.tsx`), ranked below `/sign-in`, `/claim`, `/home`, `/inbox`, `/map`, `/my-link` and `/settings` (reserved names). `beforeLoad` redirects a name with capitals to its lowercase form (`replace`). The page sets `document.title` to "Send <display name> an anonymous drop" and restores it on leave. It renders inside `AuthShell` as one `.auth-card`. States: loading, not found (also for invalid or reserved names, with no request), load error (message in `role="alert"`), closed (no form: heading "<name> is not taking drops right now", `LINK_CLOSED_MESSAGE`, a link home), open (the statement card, then the form), sent. The public profile carries `statement` (`PublicStatement`: `text`, `ends_at`, `seconds_left`) or null. The page is open only while that statement is running: the card shows the text in quotes (as text only) and a `role="timer"` line with the time left from `useCountdown(seconds_left, ends_at)`, and the page switches to closed on its own when the countdown reaches zero, or when a send is turned away as closed, with no request. `safeAvatarUrl` shows an avatar only when it is `https:` or a same-origin path starting with a single `/`; otherwise the first letter of the display name is shown.
- **Rules** (`lib/drops/model.ts`): `MESSAGE_MAX` 280, `MESSAGE_MESSAGE`, `LOCATION_MESSAGE`, `LOCATION_REQUIRED_MESSAGE`, `LINK_CLOSED_MESSAGE` ("This link is not taking drops right now."), `STATEMENT_FILTER_MESSAGE` ("That statement is not valid."), `PHOTO_MAX_BYTES` (8 MB), `PHOTO_MESSAGE`, `PHOTO_UNREADABLE_MESSAGE` and `PHOTO_TYPES` (`image/jpeg`, `image/png`, `image/webp`) are copied from `backend/src/drops/model.ts` and `backend/src/photos/model.ts` and kept in step with them. `validPhoto(file)` is true for an allowed type of 1 byte up to `PHOTO_MAX_BYTES`. `validateDraft(draft)` returns `{ ok: true }` or `{ ok: false, message }`: the message trimmed, 1 to 280 code points, no NUL; a location is required (missing gives `LOCATION_REQUIRED_MESSAGE`), needs both coordinates in range, and a source of `gps` (any other source gives `LOCATION_REQUIRED_MESSAGE`); then a photo, if present, must pass `validPhoto` or the result is `PHOTO_MESSAGE`. `formatCoordinate` gives a 6 decimal string, never exponent form. Types `LocationSource`, `DropLocation`, `DropDraft` (`{ message, location, photo: File | null }`).
- **Call** (`lib/drops/api.ts`): `sendDrop(username, draft)` posts `FormData` (`message`, `latitude`, `longitude`, `location_source`, always; `photo` only when the draft has one) to `/api/v1/profiles/<name>/drops` and resolves `{ delivered: true }`. The server cleans the photo and decides; `PHOTO_UNREADABLE_MESSAGE` is what it answers for a file it cannot read.
- **Hooks.**
    - `usePublicProfile(username)` returns `{ status, profile, error }` with status `loading | ready | not-found | error`. It lowercases the name and checks it with `checkUsername` first (a bad name is `not-found` with no request), then reads the public profile, which also sets the device cookie the send needs. The request aborts when the name changes or the page leaves. A 404 is `not-found`; other failures are `error` with the message.
    - `useSendDrop(username)` returns `{ status, error, closed, send, reset }` with status `idle | sending | sent | error`. `send(draft)` runs `validateDraft` first (a failure is a 422 `ApiError`, with no request), holds a ref lock so a second call while one is in flight does nothing, and sets `closed` on a 409 `LINK_CLOSED`. `reset` returns to `idle`.
    - `useGeolocation()` returns `{ status, position, request, reset }` with status `idle | locating | ready | denied | unavailable | timeout`, and `position` of `{ latitude, longitude, accuracy }` or null. Nothing is asked until `request()` runs. It uses high accuracy, a 10 s timeout and a 60 s maximum age. The position stays in memory only, and results arriving after unmount are ignored.
- **Components** (`components/drops/`).
    - `DropForm({ displayName, sending, error, onSend })`: textarea with a live code point count, a "Turn on location" button ("Finding you" while locating, "Try again" after a failure), and, once there is a fix, the GPS place row ("From your GPS", coordinates to 3 decimals, "Rounded to about 150 m", a refresh button). Denied, timeout and unavailable each show their own help text in a polite live region. Send stays disabled until there is a GPS fix, and the reason ("Turn on your location to send.") or the send error shows in a `role="alert"` slot. The place is held in memory only. There is no map and no manual place.
        - Photo field: "Add a photo (optional)" with a hidden file input (`id` `send-photo`, `name` `photo`, `accept` the three `PHOTO_TYPES`, no `capture`, so phones offer camera or gallery). On choose, `validPhoto` runs; a wrong file shows `PHOTO_MESSAGE` and is not kept. A kept photo shows a blob preview (`URL.createObjectURL`), "Photo added", its size, and a remove button. The preview address is revoked when the photo changes, is removed, or the form unmounts. The file is passed up in `onSend({ message, location, photo })`. While sending with a photo the button reads "Sending…".
    - `SentCard({ displayName, onSendAnother })`: the result card. Focus moves to its heading on mount.
- **Styles.** `styles/send.css` (imported by the route) is scoped under `.auth-page` and reuses the `auth-*` classes from `auth.css`. Tokens are `--send-*` in `styles/tokens.css`, including `--send-photo-thumb` (`clamp(4rem, 3.5rem + 2vw, 5rem)`) and `--send-photo-radius` (12px) for the photo preview; see [design.md](design.md).

## App shell

The frame every signed-in page sits in. Progress notes are in [12b-app-shell.md](../progress/12b-app-shell.md); the values are in [design.md](design.md).

- **Route tree.** `routes/_app.tsx` is a pathless layout. `beforeLoad` returns at once when `preload` is true (a hover, touch or focus preload runs no guard; the real navigation runs it), otherwise sends a signed-out visitor to `/sign-in` (`getSession()` is null). `main.tsx` creates the router with `defaultPreload: "intent"`, so a link's route code loads on hover, touch or focus. `AppLayout` loads the owner's profile once with `useOwnProfile()` and shares it through `OwnLinkContext`; status `missing` navigates to `/claim` and `signed-out` to `/sign-in` (both `replace`). It renders `<AppShell><Outlet /></AppShell>`, so the shell shows at once while the profile loads. Children: `_app.inbox` (with `_app.inbox.index` and `_app.inbox.$id` below it), `_app.map`, `_app.my-link`, `_app.settings`. Guards spare a trip; the server checks the session on every request. `/home` redirects to `/inbox`; sign-in and claim land on `/inbox`. `inbox.index.tsx` and `inbox.$id.tsx` no longer exist.
- **`AppShell({ children })`** (`components/layout/app-shell.tsx`). Root `div.auth-page.app-page`: a fixed marbled bath (`MarbleBackground intensity="chrome"`, masked so on phones it shows behind the header only), a "Skip to content" link that moves focus to `main#app-main` (`tabIndex -1`) without changing the address, `AppNav`, and `main`. Imports `styles/auth.css` and `styles/app-shell.css`.

### Map page

`routes/_app.map.tsx`, `/map`. Styles in `styles/map.css` (with `styles/inbox.css`), tokens `--map-*`.

- **Address.** `validateSearch` returns `{ filter, statement, place }`. `filter` is `unread` or `photos` (`isInboxFilter`, not `all`), otherwise `undefined`. `statement` is kept only when `isStatementFilter` accepts it, otherwise `undefined`. `place` is kept only when it matches `PLACE_KEY_PATTERN` (`^-?\d{1,2}\.\d{6},-?\d{1,3}\.\d{6}$`), otherwise `undefined`. Choosing and clearing a place, and changing the filter, use `navigate` with `replace: true`. A new filter or statement keeps the place only while it still has matching drops.
- **Place key.** `placeKey(lat, lng)` (`lib/drops/helper.ts`) is `lat,lng` at six decimals. It is the key of a `PlaceGroup` and the `place` value in the address. Also in the helper: `groupByPlace(items)` (`PlaceGroup`: `key`, `lat`, `lng`, `name`, `items`, `unread`; first-seen order, first known name) and `filterDrops(items, filter, statement?)` (the chips and the statement scope filter the loaded drops on the device; `earlier` matches drops with no statement).
- **Constants** (`lib/drops/model.ts`): `MAP_PAGE_SIZE` 50, `MAP_AUTO_PAGES` 4, `MAP_MAX_DROPS` 500, `MAP_FRESH_MS` 60 000, `PLACE_KEY_PATTERN`. `listDrops` takes an optional `limit`, sent as `limit`.
- **Map store** (`hooks/drops/map-store.ts`). One in-memory `MapSnapshot` (`status` idle, loading, ready or error; `items`, `statements`, `earlierCount`, `nextCursor`, `loadedAt`, `error`, `loadingMore`, `moreError`) with `subscribe`, `getSnapshot`, `updateMap`. It never touches storage. It listens through `onDropChange` in `inbox-store.ts` (new: `DropChange`, `onDropChange`, `setUnreadCount`; `applyReadChange` and `applyRemoval` emit changes), so a read toggle or delete anywhere updates or removes the kept item.
- **`useMapDrops()`** (`hooks/drops/use-map-drops.ts`) returns the snapshot plus `retry` and `loadOlder`. On mount it reuses a ready load younger than `MAP_FRESH_MS`; otherwise it loads up to `MAP_AUTO_PAGES` pages of `MAP_PAGE_SIZE` one after another, replacing what was kept with page one, with a generation counter and abort so late answers are dropped. Every page sets the unread count, merges its statements into `statements` and sets `earlierCount`. A failed first page is `status: "error"` with the server text (a 429 shows the wait text); a later failure sets `moreError`. No automatic retry. `loadOlder()` adds up to `MAP_AUTO_PAGES` more pages behind a ref lock, stopping at `MAP_MAX_DROPS`. A load cut short is not stamped as fresh.
- **Page.** The page shows the map stage, `FilterChips` (class `map-chips`, shown when there are drops), `StatementPicker` beside them (shown when there are statements or earlier drops), a "Load older drops" button when a cursor remains and at least `MAP_AUTO_PAGES * MAP_PAGE_SIZE` drops are loaded and fewer than the cap, a collapse button from 80rem (`aria-controls="map-list"`, `aria-expanded`), and `MapPanel`. `AllDropsMap` is lazy and mounts only once drops exist, so an account with no drops loads no map engine and sees the share-link invitation. A filter with no match shows a note ("No unread drops", "No photos yet", or "No drops from this statement" for a statement with none), with a "Show all drops" button that clears the filter, the statement and the place. The panel heading names the chosen statement. Escape clears the chosen place; focus goes to the panel heading on select and back to the pin (or the page heading) on close. `measureInsets()` reads the nav, list, chips and controls rectangles so the map keeps pins clear of them. `SIDE_QUERY` is `(min-width: 80rem)`: only from 1280px does the nav count as a left rail, so on phones and tablets the map frames pins above the bottom bar.
- **`StatementPicker({ statements, earlierCount, value, onChange })`** (`components/statements/statement-picker.tsx`): a custom listbox. A glass pill button (`aria-haspopup="listbox"`, `aria-expanded`) shows the chosen label, its drop count and a `CaretDown`. Opening it shows a list (`role="listbox"`, options with `aria-selected`, focus on the list, `aria-activedescendant`) of "All statements", one option per statement (text cut to 40 characters, with its drop count) and "Earlier" with its count (shown when there are earlier drops or it is chosen), with a `Check` on the chosen one. The list melts out of the pill through `Goo` and `GooFilter` (id `statement-picker-goo`, crisp). Keys: ArrowDown or ArrowUp on the button opens it; in the list ArrowUp, ArrowDown, Home and End move, Enter or Space chooses, Escape closes and returns focus to the button, Tab closes. A pointer press outside closes it. Choosing one calls `onChange`; the page puts it in the address.
- **`MapPanel`** (`components/drops/map-panel.tsx`): an `aside#map-list` region with a heading (takes focus), a drop count, a Close button when a place is chosen (or on phones and tablets), and `InboxCard` rows. Cards get `search={{ filter }}` only, so the place does not travel into the drop link and Back restores it. Phones: sheet over the map (`--map-sheet-max-h`); tablets: floating panel (`--map-panel-w`); 1280 and up: docked, lists all filtered drops when nothing is chosen.
- **`AllDropsMap`** (`components/drops/all-drops-map.tsx`). `react-map-gl/maplibre` with `maxBounds={WIDE_BOUNDS}`, zoom `MIN_ZOOM` to `MAX_ZOOM`, rotation and pitch off. Initial view: bounds of the chosen place or all places inside `MAX_BOUNDS`, with padding from the page's insets plus `PIN_ROOM`. Pins are `Marker` buttons (`.map-pin`, `data-place`, `aria-label`, `aria-pressed` on single places) showing the drop count always. `clusterPlaces(groups, zoom)` (`lib/map/cluster.ts`) merges places into 48 px cells below zoom 14 (`SPLIT_ZOOM`) and keeps each place separate from 14 up; a merged pin fits its places on click. A single pin selects or clears the place; the selected place eases to centre and draws the ~150 m area (`areaAround`, fill 0.18 opacity, dashed edge). ### Setting up the tiles folder

The map files live in `drop-app/tiles/` (git-ignored; `TILES_DIR` can point elsewhere) and the backend serves them at `/tiles`. In dev, Vite forwards `/tiles` to `http://localhost:3000`. The folder holds three things, none of them committed:

1. `philippines.pmtiles`: cut from a Protomaps planet build with the `pmtiles` command line tool: `pmtiles extract <source> philippines.pmtiles --bbox=116.9,4.6,126.6,21.1 --maxzoom=15`.
2. `fonts/`: the glyph folders from `protomaps/basemaps-assets` (`fonts/<fontstack>/<range>.pbf`).
3. `sprites/v4/`: the sprite files (`light.json`, `light.png` and the `@2x` pair, plus the other flavours) from the same repository.

The bounding box matches `MAX_BOUNDS` in `drop-map.tsx`. A missing folder gives a one-line warning at backend boot and plain 404s for map files. Endpoint details are in [backend.md](backend.md).

## Statements

The line an owner puts up to open their link for two hours. Progress notes are in [13-statements.md](../progress/13-statements.md); endpoints and rules are in [backend.md](backend.md).

- **Model** (`lib/statements/model.ts`). `STATEMENT_DURATION_SECONDS` 7200, `STATEMENT_MAX` 120, `STATEMENT_MESSAGE` and `STATEMENT_ENDED_MESSAGE`, copied from `backend/src/statements/model.ts` and kept in step. `normalizeStatement(text)` collapses whitespace runs to one space and trims; `checkStatement(text)` returns `{ ok: true, value }` or `{ ok: false, message }` (1 to 120 code points, no control character). Types `Statement` (`id`, `text`, `started_at`, `ends_at`, `ended_at`, `running`, `seconds_left`, `drop_count`) and `PublicStatement` (`text`, `ends_at`, `seconds_left`).
- **Calls** (`lib/statements/api.ts`). `startStatement(text)` (`POST /api/v1/me/statements`), `endStatement(id)` (`PATCH /api/v1/me/statements/<id>` with `{ ended: true }`; a malformed id rejects as a 404 with no request) and `getCurrentStatement(signal?)` (`GET /api/v1/me/statements/current`, `{ statement }`, which is never a null body because `apiRequest` treats null data as a failure).
- **Helper** (`lib/statements/helper.ts`). `timeLeftLabel(ms)` gives "1h 20m left", "4m left" or "45s left" (rounded up, never 0 before the end); `durationLabel()` gives "2 hours" from `STATEMENT_DURATION_SECONDS`.
- **Store** (`hooks/statements/statement-store.ts`). One in-memory `StatementSnapshot` (`status` idle, loading, ready or error; `statement`, `deadline`, `error`) with `subscribe`, `getSnapshot`, `update`, `setCurrent(statement)` (a statement that is not running is stored as null; the deadline is `Date.now() + seconds_left * 1000`, set once when the answer arrives), `secondsUntil(deadline)` and `markEnded()`. Never written to storage.
- **Hooks.**
    - `useCountdown(secondsLeft, key)` returns the time left in ms and a `done` flag. The deadline is set once per key from the seconds the server sent, so a wrong phone clock does not matter. It ticks every second and catches up at once on `visibilitychange`. It never asks the server for anything.
    - `useCurrentStatement()` reads the store, loads it once per app session through whichever screen asks first (a load is not cancelled when a screen closes) and again only on retry. At zero the statement is marked ended locally. Returns the snapshot plus `msLeft` and `retry`.
    - `useStartStatement()` returns `{ start, pending, error }`: `checkStatement` first (a failure shows the same message with no request), a ref lock so a double click starts one statement, `setCurrent` on success.
    - `useEndStatement()` returns `{ end, pending, error }`: a ref lock, `setCurrent(null)` on success. A 409 also closes the link and shows the server's message.
- **Components** (`components/statements/`): `RunningStatement`, `StatementForm`, `StatementBanner`, `StatementHeader`, `StatementPicker`, described under Inbox, Map page and My link. Statement text is always rendered as text, never as markup, and never placed in a link, image source or style. The link preview made by chat apps carries no statement text.
- **Styles.** `--statement-*` tokens in `styles/tokens.css`; see [design.md](design.md).

## Theme

- **Choice.** `lib/theme/model.ts`: `THEME_STORAGE_KEY` `drop-theme`, `THEME_PREFERENCES` (`light`, `dark`, `auto`), `isStoredTheme`. Light and dark are stored under the key; auto removes it, so the device decides. Only those two exact values are trusted on read.
- **Bootstrap.** `public/theme.js`, loaded by `<script src="/theme.js">` first in the head of `index.html`, reads the key in a try block and sets `data-theme` on the root element before first paint. It is a same-origin file, so the CSP needs no inline allowance. Its key and values must stay in step with `model.ts`.
- **Preference** (`lib/theme/preference.ts`). `readPreference()` (guarded; a bad stored value is removed and read as auto), `writePreference(preference)`, `applyPreference(preference)` (sets or removes `data-theme`), `followOtherTabs()` (a `storage` listener that applies the stored choice; returns the stop function). The shell calls it, and it loads no motion settings.
- **Apply** (`lib/theme/apply.ts`). `effectiveTheme(preference)` resolves auto from `prefers-color-scheme`. `switchTheme(preference, origin?)` writes the choice, then applies it at once when the shown theme does not change, when `document.startViewTransition` is missing, under reduced motion, or with no origin; otherwise it runs a view transition and animates `clip-path: circle()` on `::view-transition-new(root)` from the origin to the farthest corner, with `motionDefaults.iris` duration and easing. `app-shell.css` turns off the default cross-fade for `::view-transition-old(root)` and `::view-transition-new(root)`.
- **`useTheme()`** (`hooks/theme/use-theme.ts`) returns `{ preference, effective, choose }` from one in-memory snapshot (starts from storage, so it still works when storage is blocked), shared through `useSyncExternalStore`. It follows device colour-scheme changes and `storage` events from other tabs. `choose(next, origin?)` calls `switchTheme` and updates the snapshot.
- **`AppearanceControl()`** (`components/theme/appearance-control.tsx`): a `role="radiogroup"` labelled by `#appearance-label` with three native radios (Light, Dark, Auto). The origin of the iris is the centre of the picked option's label.
- **Landing** stays light: it sets `data-theme="light"` in a layout effect and restores the previous value on leave.

## Account deletion

Progress notes are in [13b-legal-and-account-deletion.md](../progress/13b-legal-and-account-deletion.md). The endpoint is `DELETE /api/v1/me` (see [backend.md](backend.md)).

- **`lib/account/model.ts`.** `CONFIRM_MESSAGE` ("Type your link name to confirm."), copied from the backend and kept in step with it, and `matchesUsername(input, username)`, which trims and compares without case.
- **`lib/account/api.ts`.** `deleteAccount(username)` sends `DELETE /api/v1/me` with the JSON body `{ username }` through `apiRequest`.
- **`lib/auth/client.ts`.** `forgetSession` is now exported, so the 30 second session reuse can be dropped after a deletion.
- **`useDeleteAccount()`** (`hooks/account/use-delete-account.ts`) returns `{ remove(username), pending, error }`. A lock held in a ref blocks a double click, and stays shut after success. On `204` it calls `forgetSession()` and `window.location.replace("/")`; the full load clears the inbox, map and session memory. On `401` it goes to `/sign-in`. A `429` shows the `ApiError` wait message. Anything else shows the server message as text, or "Something went wrong. Try again."
- **`DeleteAccount({ username, pending, error, onConfirm, onCancel })`.** An in-page panel (`#delete-account-panel`) in the same pattern as `DeleteConfirm`, with all four wrapper levels. Title "Delete your account?", a list of six consequences (the link stops working, every drop sent to you is deleted with its photos and places, statements are deleted, signed out on every device, the name is locked for 30 days, this cannot be undone), and a labelled input "Type {name} to confirm" (`autoComplete="off"`, `autoCapitalize="none"`, spellcheck off, `maxLength` 30). "Delete account" stays disabled until `matchesUsername` is true and while the request runs ("Deleting" while pending). Cancel takes focus when the panel opens. The error shows in `role="alert"` as text. The mismatch message shows only if a mismatching submit is forced, because the button is off.

## Contact address config

`VITE_CONTACT_EMAIL` is a public build variable: the address shown on the legal pages. It is a role address (such as `privacy@...`), never a personal one.

- **Where it is read.** `vite.config.ts` sets `envDir` to the `drop-app` root, where `.env` lives, and reads the value with `loadEnv(mode, envDir, "VITE_")`. It is checked against an email pattern and injected with `define`, so only the config chunk carries it.
- **Build.** `pnpm build` throws "VITE_CONTACT_EMAIL must be set to a valid email address for a build." when the value is missing or invalid. Set it in `drop-app/.env` and in the Railway build variables.
- **Dev.** `pnpm dev:frontend` falls back to `privacy@example.invalid` and prints a warning, because Vite restarts itself when its config changes and a hard failure would stop a running dev server.
- **In code.** `lib/config.ts` exports `CONTACT_EMAIL` and `CONTACT_MAILTO`. `vite-env.d.ts` types the variable.
- **`.env.example`** lists `VITE_CONTACT_EMAIL=hello@fundrstudio.com`.

## Sharing

The story card: a drop's owner makes a 1080 by 1920 PNG from the drop page. Progress notes are in [12-sharing.md](../progress/12-sharing.md).

- **Files.** `lib/share/model.ts` (constants, layout, colours, types), `lib/share/render.ts` (canvas drawing), `hooks/share/use-story-card.ts`, `components/share/share-sheet.tsx`, `styles/share.css`. `components/drops/drop-view.tsx` holds the "Share to story" button (`aria-expanded`, `aria-controls="share-panel"`) in the action row beside the round Delete button, and loads `ShareSheet` with `React.lazy` inside `Suspense`. Closing returns focus to the button.
- **Constants** (`lib/share/model.ts`). Card 1080 by 1920 (`CARD_WIDTH`, `CARD_HEIGHT`), `STORY_FILE_NAME` `drop-story.png`, `STORY_FILE_TYPE` `image/png`, `STORY_LOGO_PATH` `/brand/logo.svg`, `DOWNLOAD_LOCK_MS` 800, `PLACE_SOURCE_LABEL` `GPS`. `STORY_COLORS` is the light palette plus the hero marble pigments, because the card is always light. `STORY_LAYOUT` holds every position and size. Types `StoryOptions` (`{ includePhoto, includePlace }`) and `StoryInput` (`{ message, placeName, photo, link }`).
- **Drawing** (`renderStoryCard(input, options)` returns a PNG `Blob`). Waits for the logo (loaded once per page; a failed load draws the card without it) and the brand fonts. Draws wavy marble lines for the ground, the logo, the message on a paper card, the photo cover-fit in a ring-framed circle when `includePhoto` and a photo are present, the place pill (pin, name, `GPS`) when `includePlace` and a name exist, and the link on a black pill. The message shrinks from 52 to 30 px to fit; past that the last line is cut with an ellipsis. The photo circle shrinks between 420 and 220 px. The place name (40 to 26 px) and link (38 to 24 px) shrink, then end with an ellipsis. Text wraps by grapheme, and emoji fall back to system emoji fonts. The message is drawn as canvas text only.
- **Hook** `useStoryCard(source, options)`. `lib/share/render` is imported dynamically on the first build, so pages that offer a card do not carry it in their initial JS. `source` is `{ id, message, placeName, hasPhoto, link }`; `options` is `{ includePhoto, includePlace }`. Returns `{ previewUrl, ready, busy, photoAvailable, error, share, save }`.
    - The photo is loaded once per drop from `dropPhotoPath(id)` (same origin). A failed load leaves the card without it and `photoAvailable` false.
    - The card is rebuilt on every change. Each blob URL is revoked when replaced and when the panel closes.
    - `share()` uses `navigator.share({ files })` when `navigator.canShare` accepts the file, and otherwise saves like `save()`. `save()` clicks a temporary download link. A ref lock stops a second call; a save keeps the lock for `DOWNLOAD_LOCK_MS`. An `AbortError` (cancelled share) shows no error.
    - Messages: build failure "The image could not be made. Close this and try again."; share failure "Sharing did not work. Use Save image instead."
- **Component** `ShareSheet({ item, link, onClose })`. An in-page region (`#share-panel`) with a heading that takes focus on open, a close button, the preview, switches for photo (shown only when `photoAvailable`) and place (shown only when the drop has a place name), Share and Save image buttons (off until `ready` and while `busy`), the error in a live region, and the hint "In Instagram or TikTok, long-press the image to save it." Escape closes it. The link is `drop.link/<username>`, built from a username that passed `checkUsername`, and is drawn as text only.
- **Styles.** `styles/share.css`, scoped under `.auth-page`, with `--share-*` tokens in `styles/tokens.css`; see [design.md](design.md).
- **Bundle** (gzipped). The panel is a lazy chunk of about 5 KB, fetched when it opens. See the bundle table under Inbox for current sizes.

## Scrollbar

- `ScrollHairline({ lenis, source? })` renders only for `(hover: hover) and (pointer: fine)`; touch keeps the native bar. While shown, `html.sb-on` hides the native bar.
- Position comes from `source` (the landing's frame loop) or, without one, a passive scroll listener batched into `requestAnimationFrame`.
- Drag calls `lenis.scrollTo(top, { immediate: true })`; a track click calls `lenis.scrollTo(top)`. Without Lenis it uses `window.scrollTo`.
- `aria-hidden`, no focusable element. Gets class `dk` over dark ground. Hides after `shared.hideDelay` ms.
- `.scroll-area` in `index.css` is the thin bar for inner scroll areas, using the `area` tokens.
