## Tokens

- `useTweaks(folder, defaults, schema?)` from `@/lib/tweaks/use-tweaks` returns `defaults` unchanged. There is no live panel; a value is changed by editing the defaults in its `tokens.ts` file.
- `routes/playground/*` throw `notFound()` in `beforeLoad` when `!import.meta.env.DEV`. Their small route chunks are still emitted to `dist`.

## Design tokens

Values, bands, the app layout spec, motion and marble are in [design.md](design.md).

- Wrapper levels: `.section`, `.sub-section`, `.placement`, `.container` in `index.css` (components layer), spacing from `--section-padding`, `--section-gap`, `--sub-section-padding`, `--sub-section-gap`, `--placement-padding`, `--placement-gap`, `--container-padding`, `--container-gap` in `styles/tokens.css`. `.section` is capped at `--content-max`.
- Tailwind's own `container` utility is disabled with `@source not inline("container")` so the wrapper class stays fluid.
- Type scale (`@theme inline`, all `clamp()`): `text-display`, `text-heading`, `text-subheading`, `text-message-large`, `text-message`, `text-body`, `text-caption`, `text-mono`. Breakpoint `3xl` is 120rem.
- Motion tokens (`lib/motion/tokens.ts`): `fadeSlide`, `overshoot`, `bounceLand`, `springFollow`, `popScale`, `squash`, `stagger`, `pressFeedback`, `rippleReveal`, `letterStagger`, `nudge`, `iris`, `lightSweep`, `marbleDrift`, `shaderFadeIn`, `tabSpring`, `reducedFade`, plus `landingMotion` (not tweakable). Easing names come from `EASING_NAMES` in `lib/motion/easings.ts`; `cssEasing(name)` gives a `cubic-bezier()` or sampled `linear()` string for CSS and the Web Animations API.
- Marble (`lib/marble/tokens.ts`): `marbleDefaults` on the Marble folder, `MARBLE_PIGMENTS`, `MARBLE_GL`. Previewed at `/playground/marble`.
- Landing (`lib/landing/tokens.ts`): `landingDefaults` (`landingMotion` plus `load`, `card`, `streets`, `shader`), flattened to `landingFlatDefaults` for the Landing folder and rebuilt with `unflattenLandingTokens`.
- Scrollbar (`lib/scrollbar/tokens.ts`): `scrollbarDefaults` (`shared`, `hairline`, `area`), `scrollbarSchema`, `scrollbarCssVars`, `scrollAreaCssVars`.
- Goo (`lib/goo/tokens.ts`): `blur` (feGaussianBlur stdDeviation), `alphaContrast` and `alphaOffset` (feColorMatrix alpha row).

## Landing

- **Frame loop.** `useScrollTimeline({ rootRef, lenis, reduced, tokens })` runs one `requestAnimationFrame` loop. Each frame calls `lenis.raf(now)`, reads `lenis.scroll` (or `window.scrollY` without Lenis), builds `ScrollState` with `readScroll`, and calls every subscriber with `{ L, S, now, changed, relaid }`. Components subscribe through `useTimelineFrame` and read shared state with `useLanding()` (`LandingContext`).
- **Layout.** `buildLayout` measures the beats once and on resize. `groundAt(y, L)` returns `paper`, `dark` or `grey` for a page position; the nav and the scrollbar use it to flip ink.
- **Lenis** (`useLenis(enabled)`): `new Lenis({ autoRaf: false, syncTouch: false })`, held in a ref and exposed through `useSyncExternalStore`: subscribing creates the instance, unsubscribing (unmount, or `enabled` turning false) destroys it. Not created under reduced motion. In-page links go through `scrollToTarget` (`lenis.scrollTo`). The claim dialog calls `lenis.stop()` while open and `lenis.start()` on close; it carries `data-lenis-prevent`.
- **Background.** `BathPlate` owns the single canvas and drives the marble renderer in external mode (`frame(now)` from the loop). The stage gets `still-mode` when the live shader is off (reduced motion or a failure).
- **Reduced motion.** The root gets `.rm`; no Lenis, no canvas, still poster, final states.
- **Theme.** The route sets `data-theme="light"` on the root element while mounted and restores the previous value on unmount.
- **Claim.** `ClaimIris({ request, onClosed })` runs `useUsernameCheck(name)` and shows its message in `#claim-msg` ("Checking the name", "That name is free.", or the mirrored invalid, reserved or taken message; an empty submit shows the invalid message). Submit sets a waiting flag; once the check is `available` (or `idle` with a valid name, when the lookup failed) it navigates once to `/sign-in?username=<name>` behind a lock. Escape and Back close it; focus returns to the opener. Lenis stop and start are unchanged.
- **Frame cost.** Nothing in the loop reads layout: the renderer keeps the canvas CSS size from its ResizeObserver, and measurements (`buildLayout`, panel widths, photo size) run only on relayout. The hairline arms one hide timer and re-arms it for the time left, so steady scrolling sets no timer per frame.
- **Frame timing** (production build via `vite preview` on 127.0.0.1, Edge, 390x844 at dpr 3, one wheel pass over the page, script time from CDP `Performance.getMetrics`):

- **Dev hook.** In dev, `window.__landing` exposes `{ L, S }` for the browser checks.

## Auth and profiles

- **Routes.** `/sign-in` (`validateSearch: usernameFromSearch`), `/claim` (same search; `beforeLoad` redirects to `/sign-in` with the username when `getSession()` is null), `/home` (`beforeLoad` redirects to `/sign-in` when signed out, otherwise to `/inbox`). `usernameFromSearch` returns `{ username: undefined }` for an invalid value, because the router merges the raw root search under the validated one. Guards are for user experience; the server checks the session on every request.
- **Auth client** (`lib/auth/client.ts`): `createAuthClient` from `better-auth/react` with `baseURL: window.location.origin`, `basePath: "/api/auth"`, `plugins: [emailOTPClient()]`. `sendCode(email)` calls `emailOtp.sendVerificationOtp({ type: "sign-in" })`, `verifyCode(email, otp)` calls `signIn.emailOtp`, then `signOut()`, `getSession()` (data or null), `useSession`. Failures become `ApiError`; a 429 reads `X-Retry-After` into `rateLimitMessage`.
- **Fetch wrapper** (`lib/api.ts`): `apiRequest<T>(path, init)` sends `Content-Type: application/json` only when `init.body` is a string, so a `FormData` body gets no content type and the browser adds the multipart boundary. It uses `credentials: "same-origin"`, unwraps `{ data, error }`, throws `ApiError(status, code, message)`. A `204` has no body and resolves `undefined` (delete). 429 reads `Retry-After` ("Too many tries. Try again in N seconds."). Network failure is status 0, `NETWORK_ERROR`. 5xx messages are replaced with a generic one. Aborts rethrow the `AbortError`.
- **Profile model** (`lib/profiles/model.ts`): `RESERVED_USERNAMES` and the five message constants copied from `backend/src/profiles/model.ts`; `checkUsername` (trim, lowercase, 3 to 30 of `[a-z0-9_.]`, not reserved), `checkDisplayName` (trimmed, 1 to 50), `usernameFromSearch`; types `PublicProfile`, `OwnProfile`, `CreateProfileInput`, `UpdateProfileInput`. Must stay in step with the backend file.
- **Profile calls** (`lib/profiles/api.ts`): `getPublicProfile(username, signal?)`, `getOwnProfile(signal?)`, `createProfile(input)`, `updateOwnProfile(input)`.
- **Hooks.** `useUsernameCheck(input)` returns `{ status, message, username }` with status `idle | checking | available | taken | invalid`: the client rule first (no request), then `GET /api/v1/profiles/:username` after 350ms (404 available, 200 taken), aborting the previous request; other failures give `idle` with the error message. `useOwnProfile()` returns `loading | ready | missing (404) | signed-out (401) | error`. `useCreateProfile()` returns `{ create, pending, error, clearError }`; a ref lock allows one request at a time and stays shut after success.
- **Sign-in.** Email checked against a simple pattern (max 254). After sending: "If that email can sign in, a code is on its way."; resend locked 60s with an `m:ss` countdown. The code input is `inputmode="numeric"`, `autocomplete="one-time-code"`, digits only, cut to 6 (no `maxLength`, so a pasted "123 456" survives). Every verify failure other than 429 or network shows "That code did not work. Check it or send a new one." After verify, `GET /me/profile` 200 goes to `/inbox`, anything else to `/claim` (which checks again).
- **Claim.** 409 `USERNAME_TAKEN` shows on the name field; 409 `PROFILE_EXISTS` or an existing profile goes to `/inbox`; a successful claim also goes to `/inbox`; 401 goes to `/sign-in`; 422 and 429 show under the form.
- **Styles.** `--auth-*` tokens in `styles/tokens.css` (card max width, padding and gap per band, radii, field and button heights, focus ring, enter motion, `clamp()` type for title, code and link). The card enters with a 600ms fade and 24px rise; under reduced motion a 200ms fade only, and the marble shows its still.

## Send page

- **Route.** `/$username` (`routes/$username.tsx`), ranked below `/sign-in`, `/claim`, `/home`, `/inbox`, `/map`, `/my-link` and `/settings` (reserved names). `beforeLoad` redirects a name with capitals to its lowercase form (`replace`). The page sets `document.title` to "Send <display name> an anonymous drop" and restores it on leave. It renders inside `AuthShell` as one `.auth-card`. States: loading, not found (also for invalid or reserved names, with no request), load error (message in `role="alert"`), paused (no form, `LINK_PAUSED_MESSAGE`, link home), form, sent. `safeAvatarUrl` shows an avatar only when it is `https:` or a same-origin path starting with a single `/`; otherwise the first letter of the display name is shown.
- **Rules** (`lib/drops/model.ts`): `MESSAGE_MAX` 280, `MESSAGE_MESSAGE`, `LOCATION_MESSAGE`, `LOCATION_REQUIRED_MESSAGE`, `LINK_PAUSED_MESSAGE`, `PHOTO_MAX_BYTES` (8 MB), `PHOTO_MESSAGE`, `PHOTO_UNREADABLE_MESSAGE` and `PHOTO_TYPES` (`image/jpeg`, `image/png`, `image/webp`) are copied from `backend/src/drops/model.ts` and `backend/src/photos/model.ts` and kept in step with them. `validPhoto(file)` is true for an allowed type of 1 byte up to `PHOTO_MAX_BYTES`. `validateDraft(draft)` returns `{ ok: true }` or `{ ok: false, message }`: the message trimmed, 1 to 280 code points, no NUL; a location is required (missing gives `LOCATION_REQUIRED_MESSAGE`), needs both coordinates in range, and a source of `gps` (any other source gives `LOCATION_REQUIRED_MESSAGE`); then a photo, if present, must pass `validPhoto` or the result is `PHOTO_MESSAGE`. `formatCoordinate` gives a 6 decimal string, never exponent form. Types `LocationSource`, `DropLocation`, `DropDraft` (`{ message, location, photo: File | null }`).
- **Call** (`lib/drops/api.ts`): `sendDrop(username, draft)` posts `FormData` (`message`, `latitude`, `longitude`, `location_source`, always; `photo` only when the draft has one) to `/api/v1/profiles/<name>/drops` and resolves `{ delivered: true }`. The server cleans the photo and decides; `PHOTO_UNREADABLE_MESSAGE` is what it answers for a file it cannot read.
- **Hooks.**
    - `usePublicProfile(username)` returns `{ status, profile, error }` with status `loading | ready | not-found | error`. It lowercases the name and checks it with `checkUsername` first (a bad name is `not-found` with no request), then reads the public profile, which also sets the device cookie the send needs. The request aborts when the name changes or the page leaves. A 404 is `not-found`; other failures are `error` with the message.
    - `useSendDrop(username)` returns `{ status, error, paused, send, reset }` with status `idle | sending | sent | error`. `send(draft)` runs `validateDraft` first (a failure is a 422 `ApiError`, with no request), holds a ref lock so a second call while one is in flight does nothing, and sets `paused` on a 409 `LINK_PAUSED`. `reset` returns to `idle`.
    - `useGeolocation()` returns `{ status, position, request, reset }` with status `idle | locating | ready | denied | unavailable | timeout`, and `position` of `{ latitude, longitude, accuracy }` or null. Nothing is asked until `request()` runs. It uses high accuracy, a 10 s timeout and a 60 s maximum age. The position stays in memory only, and results arriving after unmount are ignored.
- **Components** (`components/drops/`).
    - `DropForm({ displayName, sending, error, onSend })`: textarea with a live code point count, a "Turn on location" button ("Finding you" while locating, "Try again" after a failure), and, once there is a fix, the GPS place row ("From your GPS", coordinates to 3 decimals, "Rounded to about 150 m", a refresh button). Denied, timeout and unavailable each show their own help text in a polite live region. Send stays disabled until there is a GPS fix, and the reason ("Turn on your location to send.") or the send error shows in a `role="alert"` slot. The place is held in memory only. There is no map and no manual place.
        - Photo field: "Add a photo (optional)" with a hidden file input (`id` `send-photo`, `name` `photo`, `accept` the three `PHOTO_TYPES`, no `capture`, so phones offer camera or gallery). On choose, `validPhoto` runs; a wrong file shows `PHOTO_MESSAGE` and is not kept. A kept photo shows a blob preview (`URL.createObjectURL`), "Photo added", its size, and a remove button. The preview address is revoked when the photo changes, is removed, or the form unmounts. The file is passed up in `onSend({ message, location, photo })`. While sending with a photo the button reads "Sending…".
    - `SentCard({ displayName, onSendAnother })`: the result card. Focus moves to its heading on mount.
- **Styles.** `styles/send.css` (imported by the route) is scoped under `.auth-page` and reuses the `auth-*` classes from `auth.css`. Tokens are `--send-*` in `styles/tokens.css`, including `--send-photo-thumb` (`clamp(4rem, 3.5rem + 2vw, 5rem)`) and `--send-photo-radius` (12px) for the photo preview; see [design.md](design.md).

## App shell

The frame every signed-in page sits in. Progress notes are in [12b-app-shell.md](../progress/12b-app-shell.md); the values are in [design.md](design.md).

- **Route tree.** `routes/_app.tsx` is a pathless layout. `beforeLoad` sends a signed-out visitor to `/sign-in` (`getSession()` is null). `AppLayout` loads the owner's profile once with `useOwnProfile()` and shares it through `OwnLinkContext`; status `missing` navigates to `/claim` and `signed-out` to `/sign-in` (both `replace`). It renders `<AppShell><Outlet /></AppShell>`, so the shell shows at once while the profile loads. Children: `_app.inbox` (with `_app.inbox.index` and `_app.inbox.$id` below it), `_app.map`, `_app.my-link`, `_app.settings`. Guards spare a trip; the server checks the session on every request. `/home` redirects to `/inbox`; sign-in and claim land on `/inbox`. `inbox.index.tsx` and `inbox.$id.tsx` no longer exist.
- **`AppShell({ children })`** (`components/layout/app-shell.tsx`). Root `div.auth-page.app-page`: a fixed marbled bath (`MarbleBackground intensity="chrome"`, masked so on phones it shows behind the header only), a "Skip to content" link that moves focus to `main#app-main` (`tabIndex -1`) without changing the address, `AppNav`, and `main`. Imports `styles/auth.css` and `styles/app-shell.css`.
- **`AppNav()`** (`components/layout/app-nav.tsx`). A `nav` labelled "Main" with the tabs Inbox (`/inbox`), Map (`/map`), My link (`/my-link`), Settings (`/settings`), each a router `Link` with a Phosphor icon (fill weight when active, bold otherwise). A tab owns every address that equals or starts with its path, so `/inbox/<id>` keeps Inbox active. A bead layer sits behind the tabs: a lead and a slower trail bead through `GooFilter` and `Goo` (id `app-nav-goo`), positioned by `--nav-index`, with duration and easing from `sampleSpring(motionDefaults.tabSpring)` set as `--app-bead-dur` and `--app-bead-ease`. Under reduced motion the bead jumps without travel. The Inbox tab shows `unreadCount` from the inbox store through `useSyncExternalStore`: nothing while it is null or 0, otherwise the number, capped at `9+` (`COUNT_CAP` 9), with the accessible name "Inbox, N unread". The logo (both theme images) and `LinkFoot` (link text, a Copy button, a status line, from `useOwnLink` and `useLinkShare`) are hidden below 80rem.
- **`useWide()`** (`hooks/layout/use-wide.ts`) returns true at `(min-width: 80rem)`, following the media query live through `useSyncExternalStore`. The query must match the laptop band in `tokens.css` and `app-shell.css`.
- **`useOwnLink()`** (`hooks/profiles/use-own-link.ts`) reads `OwnLinkContext` and returns `{ status, link, displayName, message }`. `link` is `linkText(username)` when the profile is ready, otherwise `""`. `message` is the error text when status is `error`.
- **`linkText(username)`** (`lib/profiles/helper.ts`) returns `drop.link/<name>` when `checkUsername` accepts the name, otherwise `""`. The result is display text, never an `href`.
- **`useLinkShare(link)`** (`hooks/profiles/use-link-share.ts`) returns `{ copy, share, busy, message }`. `copy()` writes `https://<link>` to the clipboard ("Link copied." or "Copy did not work. Select the link and copy it."). `share()` calls `navigator.share({ url })` when it exists, and otherwise, or on a failure other than `AbortError`, copies; a closed share sheet says nothing. One ref lock covers both; nothing runs without a link.
- **`LinkCard()`** (`components/profiles/link-card.tsx`) shows the link as large text with Copy and Share buttons and a status line (`role="status"`). While the profile loads it says "Loading"; on failure the error shows in `role="alert"`.
- **`useSignOut()`** (`hooks/auth/use-sign-out.ts`) returns `{ signOut, pending, error }`. `signOut()` holds a ref lock, calls `signOut` from `lib/auth/client.ts`, then navigates to `/sign-in` (`replace`). A 429 shows its wait message; any other failure shows "Could not sign out. Try again." and releases the lock.
- **Pages.** `/map` holds a heading ("Map") and one line saying the map is coming soon. `/my-link` holds the heading and `LinkCard`. `/settings` holds the heading and a Sign out button (shows "Signing out" while pending, error in `role="alert"`). Each is a `section` inside `div.app-sheet`.

## Inbox

- **Routes.** `routes/_app.inbox.tsx` has `validateSearch` returning `{ filter }`, where `filter` is `unread` or `photos` when `isInboxFilter` accepts the value and is not `all`, otherwise `undefined` (so the address for all drops carries no filter and any other value falls back to all). `InboxLayout` reads `useParams({ strict: false })` and `useWide()`: it renders `div.app-panes` (`data-open` when an id is present) with the list pane (`InboxList`) when there is no id or the screen is wide, and the reading pane (`<Outlet />`) when the screen is wide or an id is present. On phones and tablets the list and an open drop take turns; from 80rem both show. `_app.inbox.index.tsx` is the reading pane with no drop open: a marble patch, "Pick a drop to read it" and a hint, shown only when wide. `_app.inbox.$id.tsx` renders `<DropView key={id} id={id} wide={wide} />`; the key rebuilds the view for each drop, so a revealed photo, the map position and an open delete or share panel never carry over.
- **Store** (`hooks/drops/inbox-store.ts`). One in-memory snapshot per tab, never written to storage, with `subscribe(listener)`, `getSnapshot()`, `setSnapshot(next)` and `update(change)`. `InboxSnapshot` is `{ filter, status ("loading" | "ready" | "error"), items, nextCursor, unreadCount (number | null), error, loadingMore, moreError }`. `applyReadChange(item, wasRead)` replaces the kept copy and moves `unreadCount` by one in the direction of the change. `applyRemoval(id, wasUnread)` drops the item and lowers the count when it was unread. The count never goes below 0 and stays null until the first page arrives.
- **Model** (`lib/drops/model.ts`). `InboxItem` (`id`, `message`, `location { lat, lng, name, source }`, `has_photo`, `is_read`, `created_at`); `InboxPage` (`items`, `next_cursor`, `unread_count`); `InboxFilter` and `INBOX_FILTERS` (`all`, `unread`, `photos`); `isInboxFilter(value)`; `isDropId` (a UUID check applied before any id goes into a path). Messages copied from `backend/src/drops/model.ts`: `LIMIT_MESSAGE`, `CURSOR_MESSAGE`, `IS_READ_MESSAGE`, and `FILTER_MESSAGE` ("Choose a filter: all, unread or photos."), which mirrors the server's filter error.
- **Calls** (`lib/drops/api.ts`). `listDrops({ cursor, filter }, signal?)` (`GET /api/v1/drops`; `filter` is sent only when it is not `all`, the cursor only when present), `getDrop(id, signal?)`, `setDropRead(id, isRead)` (`PATCH`), `deleteDrop(id)` (`DELETE`, resolves `undefined`), and `dropPhotoPath(id)`, which returns `/api/v1/drops/<id>/photo` for a valid id and `null` otherwise. The photo is loaded by an `<img>` from that path, never through `apiRequest`.
- **Helper** (`lib/drops/helper.ts`). `shortAgo(iso, now?)` gives "now", then `Nm`, `Nh`, `Nd` up to 6d, then a short date (with the year when it is not the current one). `dayTime(iso, now?)` gives "Today, 2:26 PM", "Yesterday, 2:26 PM" or "Oct 27, 2:26 PM". `groupByDay(items, now?)` returns `{ today, earlier }` by the local calendar day, keeping the server's order. `fullTime(iso)` gives the local date and time. All return an empty string (or empty groups) for an invalid time.
- **Hooks.**
    - `useInbox(filter)` returns `{ ...snapshot, retry, loadMore }`. Page one loads on mount, on a filter change and on retry, cancelling any earlier load and load-more (a generation counter drops late answers). The same filter keeps its list on screen while it reloads; a new filter starts empty, so a list from the old filter is never shown under the new one. Each page writes `unreadCount` from `unread_count`. `loadMore()` sends the last `next_cursor` for the same filter behind a ref lock and skips items already shown.
    - `useDrop(id)` returns `{ state, retry, update }` with state `loading | ready | not-found | signed-out | error`. A malformed id is `not-found` with no request; 404 is `not-found`; 401 is `signed-out`. The request aborts when the id changes or the page leaves.
    - `useMarkRead()` returns `{ mark, pending, error }`. `mark(id, isRead, wasRead)` holds a ref lock, calls `applyReadChange` on success and resolves the updated item, or null.
    - `useDeleteDrop()` returns `{ remove, pending, error }`. `remove(id, wasUnread)` holds a ref lock that stays shut after success, treats a 404 as deleted, and calls `applyRemoval`.
- **Components** (`components/drops/`).
    - `InboxList({ filter })`: a `section` labelled by the "Inbox" `h1` (`id inbox-title`, focusable so it can take focus after a delete), the logo (phones only), "N new" when the count is known, and `FilterChips`. Below: failed (message and "Try again"), first load ("Loading your drops"), empty for the filter, or the groups. `EMPTY_COPY` holds the three empty states (All: "No drops yet" with a "Share my link" button that uses `useLinkShare`; Unread: "No unread drops"; Photos: "No photos yet"; the last two offer "Show all drops"). Today and Earlier groups are built by `CardGroup` (the Today heading is screen reader only). "Load more" and a late error show below while a cursor exists. Choosing a chip navigates to `.` with `search` filter (`undefined` for all) and `replace: true`.
    - `FilterChips({ value, onChange })`: a `role="group"` labelled "Filter drops" with one `button` per filter and `aria-pressed` on the active one.
    - `InboxCard({ item })`: a router link to `/inbox/$id` that keeps the search (`search={(prev) => prev}`), so the filter survives. Shows the message clamped to `--inbox-item-lines` lines, a place badge (left out when the name is null), a "Photo" badge, `shortAgo` in a `time` element (full time in the title), and a ringed red dot with screen reader text "Unread." when unread. The router marks the open drop's card active.
    - `DropView({ id, wide })`: the drop page (see Drop page below).
    - `DropMap({ latitude, longitude })`: `react-map-gl/maplibre` over `maplibre-gl`, with `maxBounds` [116.9, 4.6, 126.6, 21.1], zoom 5 to 15 (start 14), rotation and pitch off, the default attribution control off. A GeoJSON circle of about 150 m (64 steps) in `#FF3131` (the value of `--accent-fill`, as MapLibre paint takes colours, not CSS variables) marks the rounded point. Glass buttons (`.inbox-map-btn`, 44px) labelled "Zoom in", "Zoom out" and "Back to the drop" (flies to the drop at zoom 14), and an "About 150 m" label. The drop view loads it with `React.lazy` inside `Suspense`.
    - `PhotoReveal({ id })`: one button, three stages. `hidden` (blurred by `--inbox-photo-blur`, label "Tap to view photo"), `shown` (clear, in a ringed circle; label "Photo sent with this drop. Open it full size"), `full` (the whole photo uncropped in a 4:5 frame across the media row; label "Photo sent with this drop. Make it smaller"). `aria-expanded` follows the stage. The image source is `dropPhotoPath(id)` and nothing renders when that is null. A failed load shows "The photo could not be loaded.".
    - `DeleteConfirm({ pending, error, onConfirm, onCancel })`: Delete and Cancel side by side; focus moves to Cancel on mount; both buttons are off while the delete runs; a failure shows as text inside it.
- **Drop page** (`DropView`). The heading is `h1` ("Anonymous drop", screen reader only) alone and `h2` beside the list; the not-found view shows its heading. A bar holds the back link ("Back to inbox", keeps the search), the `dayTime` label in a `time` element, and a read toggle button labelled "Mark read" or "Mark unread". The body shows the message large, a place badge ("Place unknown" when the name is null) and a "GPS" badge, then the map and, when `has_photo`, the photo. The action row holds "Share to story" (`aria-expanded`, `aria-controls="share-panel"` while open; shown only when the owner's link is known) and a round "Delete" button; Delete swaps the row for `DeleteConfirm`. `ShareSheet` loads lazily when opened; closing returns focus to the Share button. Opening an unread drop marks it read once (a ref remembers the id). After a delete it navigates to `/inbox` keeping the search (`replace`) and focuses `#inbox-title`. A malformed id or a 404 shows "This drop is not here" with "It may have been deleted, or the link is wrong."; an error shows the message and "Try again"; 401 goes to `/sign-in`.
- **Map setup.** Everything loads from the same origin, so the CSP needs no extra source.
    - `buildMapStyle(window.location.origin)` (`lib/map/style.ts`) returns a MapLibre style: `glyphs` `<origin>/tiles/fonts/{fontstack}/{range}.pbf`, `sprite` `<origin>/tiles/sprites/v4/light`, and a vector source `pmtiles://<origin>/tiles/philippines.pmtiles`. The layers come from `@protomaps/basemaps` (`layers`, `namedFlavor("light")`) with colours taken from the Drop palette (`MARBLE_PIGMENTS.light`, paper and ink-2), labels in English.
    - Worker and protocol: `drop-map.tsx` calls `maplibregl.setWorkerUrl(workerUrl)` with the worker file imported through `maplibre-gl/dist/maplibre-gl-worker.mjs?url`, and `maplibregl.addProtocol("pmtiles", new Protocol().tile)`, both once when the chunk loads. The MapLibre stylesheet is imported in the same file.
    - Only `drop-map.tsx` and `lib/map/style.ts` import the map libraries, and only the drop route imports `drop-map.tsx`, lazily, so the map code, its stylesheet and its worker load on a drop's page only.
    - Attribution: `attributionControl` is off. `.inbox-map-credit` shows three links in the corner: OpenStreetMap copyright, Protomaps, and "Search by LocationIQ.com" (required by the LocationIQ free plan). Each opens in a new tab with `rel="noopener noreferrer"`.
- **Styles.** `styles/inbox.css` (imported by `_app.inbox.tsx`) and `styles/app-shell.css` (imported by `AppShell`) are scoped under `.auth-page` and reuse the `auth-*` classes. Tokens are `--app-*` and `--inbox-*` in `styles/tokens.css`; see [design.md](design.md).

### Setting up the tiles folder

The map files live in `drop-app/tiles/` (git-ignored; `TILES_DIR` can point elsewhere) and the backend serves them at `/tiles`. In dev, Vite forwards `/tiles` to `http://localhost:3000`. The folder holds three things, none of them committed:

1. `philippines.pmtiles`: cut from a Protomaps planet build with the `pmtiles` command line tool: `pmtiles extract <source> philippines.pmtiles --bbox=116.9,4.6,126.6,21.1 --maxzoom=15`.
2. `fonts/`: the glyph folders from `protomaps/basemaps-assets` (`fonts/<fontstack>/<range>.pbf`).
3. `sprites/v4/`: the sprite files (`light.json`, `light.png` and the `@2x` pair, plus the other flavours) from the same repository.

The bounding box matches `MAX_BOUNDS` in `drop-map.tsx`. A missing folder gives a one-line warning at backend boot and plain 404s for map files. Endpoint details are in [backend.md](backend.md).

## Sharing

The story card: a drop's owner makes a 1080 by 1920 PNG from the drop page. Progress notes are in [12-sharing.md](../progress/12-sharing.md).

- **Files.** `lib/share/model.ts` (constants, layout, colours, types), `lib/share/render.ts` (canvas drawing), `hooks/share/use-story-card.ts`, `components/share/share-sheet.tsx`, `styles/share.css`. `components/drops/drop-view.tsx` holds the "Share to story" button (`aria-expanded`, `aria-controls="share-panel"`) in the action row beside the round Delete button, and loads `ShareSheet` with `React.lazy` inside `Suspense`. Closing returns focus to the button.
- **Constants** (`lib/share/model.ts`). Card 1080 by 1920 (`CARD_WIDTH`, `CARD_HEIGHT`), `STORY_FILE_NAME` `drop-story.png`, `STORY_FILE_TYPE` `image/png`, `STORY_LOGO_PATH` `/brand/logo.svg`, `DOWNLOAD_LOCK_MS` 800, `PLACE_SOURCE_LABEL` `GPS`. `STORY_COLORS` is the light palette plus the hero marble pigments, because the card is always light. `STORY_LAYOUT` holds every position and size. Types `StoryOptions` (`{ includePhoto, includePlace }`) and `StoryInput` (`{ message, placeName, photo, link }`).
- **Drawing** (`renderStoryCard(input, options)` returns a PNG `Blob`). Waits for the logo (loaded once per page; a failed load draws the card without it) and the brand fonts. Draws wavy marble lines for the ground, the logo, the message on a paper card, the photo cover-fit in a ring-framed circle when `includePhoto` and a photo are present, the place pill (pin, name, `GPS`) when `includePlace` and a name exist, and the link on a black pill. The message shrinks from 52 to 30 px to fit; past that the last line is cut with an ellipsis. The photo circle shrinks between 420 and 220 px. The place name (40 to 26 px) and link (38 to 24 px) shrink, then end with an ellipsis. Text wraps by grapheme, and emoji fall back to system emoji fonts. The message is drawn as canvas text only.
- **Hook** `useStoryCard(source, options)`. `source` is `{ id, message, placeName, hasPhoto, link }`; `options` is `{ includePhoto, includePlace }`. Returns `{ previewUrl, ready, busy, photoAvailable, error, share, save }`.
    - The photo is loaded once per drop from `dropPhotoPath(id)` (same origin). A failed load leaves the card without it and `photoAvailable` false.
    - The card is rebuilt on every change. Each blob URL is revoked when replaced and when the panel closes.
    - `share()` uses `navigator.share({ files })` when `navigator.canShare` accepts the file, and otherwise saves like `save()`. `save()` clicks a temporary download link. A ref lock stops a second call; a save keeps the lock for `DOWNLOAD_LOCK_MS`. An `AbortError` (cancelled share) shows no error.
    - Messages: build failure "The image could not be made. Close this and try again."; share failure "Sharing did not work. Use Save image instead."
- **Component** `ShareSheet({ item, link, onClose })`. An in-page region (`#share-panel`) with a heading that takes focus on open, a close button, the preview, switches for photo (shown only when `photoAvailable`) and place (shown only when the drop has a place name), Share and Save image buttons (off until `ready` and while `busy`), the error in a live region, and the hint "In Instagram or TikTok, long-press the image to save it." Escape closes it. The link is `drop.link/<username>`, built from a username that passed `checkUsername`, and is drawn as text only.
- **Styles.** `styles/share.css`, scoped under `.auth-page`, with `--share-*` tokens in `styles/tokens.css`; see [design.md](design.md).
- **Bundle** (gzipped). The panel is a lazy chunk of about 5 KB, fetched when it opens. See the bundle table under Inbox for current sizes.

## Scrollbar

- `ScrollHairline({ lenis, source? })` renders only for `(hover: hover) and (pointer: fine)`; touch keeps the native bar. While shown, `html.sb-on` hides the native bar.
- Position comes from `source` (the landing's frame loop) or, without one, a passive scroll listener batched into `requestAnimationFrame`.
- Drag calls `lenis.scrollTo(top, { immediate: true })`; a track click calls `lenis.scrollTo(top)`. Without Lenis it uses `window.scrollTo`.
- `aria-hidden`, no focusable element. Gets class `dk` over dark ground. Hides after `shared.hideDelay` ms.
- `.scroll-area` in `index.css` is the thin bar for inner scroll areas, using the `area` tokens.
